Coupang Interview Prep Catalog

Coupang is a large e-commerce and logistics company, so its engineering interviews reward strong fundamentals, high-scale design skill and an ownership mindset. The structure below is based on public interview guides that describe an Amazon-style loop, including leadership-principle questions and a Bar Raiser round. Treat the exact round format as a strong guess and confirm it with your recruiter.

A1 The Coupang loop at a glance

Plan your time in proportion to how much each round can sink you. As a rough split: 35% coding, 30% design (low-level plus system design), 15% language and data fundamentals, 20% behavioral.

Round What it tests Prep weight
Online assessment or phone screen 1-2 LeetCode Medium problems, timed 15%
Coding (DSA) Medium to Hard problems, complexity trade-offs, clean code 20%
Low-level design Class modeling, design patterns, thread safety 15%
High-level design Scale, sharding, caching, failure handling 30%
Behavioral and Bar Raiser Ownership, customer obsession, disagree and commit, scope of impact 20%

The Bar Raiser is reported to have an independent say on the hire, so prepare it as seriously as the technical rounds.

Technologies to be comfortable with

  • Languages: Java is the most widely used (Go, Python and C++ also appear). Know concurrency and memory management well in your chosen language.

  • Distributed systems: microservices, API gateways, event-driven design with Kafka or RabbitMQ, distributed caching with Redis, job schedulers.

  • Databases: PostgreSQL and MySQL (indexing, isolation levels) and NoSQL such as DynamoDB and MongoDB, with trade-offs for high-throughput transactional systems.

  • Cloud and operations: Docker, Kubernetes, CI/CD, metrics and tracing for observability.

  • Domain bonus: inventory management, delivery routing and optimization, large-scale data processing.

A2 8-week preparation plan

Spend about 2 hours on weekdays (60-90 minutes on problems, 30 minutes on theory) and 4 hours on weekends (one timed mock plus review). If your interview is sooner, compress each stage proportionally but keep the order.

Week Focus Output
1-2 Arrays, strings, hashing, two pointers, sliding window, binary search, stacks 40 problems and a pattern notebook
3-4 Trees, graphs, heaps, intervals, backtracking 40 problems and 2 timed mocks

6 Low-level design: patterns plus 6 designs coded 6 compiling mini-projects with tests

A3 Coding rounds: DSA catalog

Aim for about 150 problems in total, mostly Medium with around 30 Hard. Learn a pattern first, then solve 5-8 problems on it. For every problem, state the brute-force approach and its complexity before optimizing.

Coupang-flavored practice: delivery routing (shortest path with constraints), inventory and order batching (interval and heap problems), delayed task schedulers (heap plus time), and rate limiters and sliding-window counters.

Execution checklist for every problem

  • Restate the problem and confirm edge cases and input sizes.

  • State the brute force and its complexity.

  • Optimize, then say the final time and space complexity out loud.

  • Code cleanly, then dry-run one normal and one edge case.

  • Practice in a plain editor or a timed HackerRank-style environment, not an IDE with autocomplete.

A4 Java language and concurrency

Java is the safest primary choice. Interviewers probe several layers below the framework, so be ready to explain internals, not just usage.

Area Know cold
Collections HashMap internals (hashing, resize, treeification), ConcurrentHashMap, ArrayList vs LinkedList, PriorityQueue, the equals and hashCode contract
Memory and JVM Heap generations, G1 vs ZGC, GC tuning basics, memory leaks, reading heap and thread dumps, Java memory model and happens-before
Concurrency synchronized vs ReentrantLock, volatile, atomics and CAS, ExecutorService and thread-pool sizing, CompletableFuture, deadlocks, producer-consumer with BlockingQueue
Modern Java Streams, records, virtual threads (Java 21), Optional, sealed classes
Spring Boot Bean lifecycle, transaction propagation and pitfalls, connection-pool tuning, circuit breakers (Resilience4j), async and timeouts
Go or Python (if chosen) Go: goroutines, channels, select, context. Python: GIL implications, asyncio, generators

Hands-on exercises: implement a thread-safe LRU cache, a bounded blocking queue using wait and notify, a token-bucket rate limiter, and a simple scheduled-task executor. For each, be ready to explain the locking strategy you chose and why.

A5 Low-level design

LLD rounds ask for runnable, extensible, thread-safe classes in 45-60 minutes. Clarify requirements, list the entities, define interfaces, code the core flow, then discuss extension points.

Patterns to know, with a concrete use

  • Strategy: pricing rules, routing algorithms, eviction policies.

  • Factory and Builder: order and shipment objects.

  • Observer: order status notifications.

  • State: order or shipment lifecycle.

  • Singleton (thread-safe): configuration and registries.

  • Circuit Breaker and Retry with backoff: calls to downstream services.

  • Chain of Responsibility: validation and fraud checks.

# Practice design What it tests

2 Rate limiter (token bucket, sliding window) Concurrency, time handling
3 Order processing pipeline State machine, idempotency, validation chain
4 Inventory reservation service Atomic updates, preventing overselling

7 Notification service (email, SMS, push) Strategy, queueing, retry

10 Splitwise-style ledger Modeling, consistency

SOLID principles are asked directly. Prepare one example of each from your own codebases.

A6 High-level design overview

Use one framework every time: requirements and scale numbers, APIs, data model, high-level diagram, a deep dive on the hardest component, then failure modes and trade-offs. Always do capacity math out loud. The System Design track teaches the seven underlying topics in depth, with diagrams, questions and answers.

Problem Hard parts to cover
Flash-sale or Rocket-Delivery-style order system Traffic spikes, queue-based load leveling, inventory reservation, idempotent checkout
Real-time inventory lookup Read-heavy caching, stock consistency across warehouses, bounds on staleness
Distributed delayed-task scheduler Time-bucketed storage, exactly-once firing, failover
Delivery routing and slot assignment Geo indexing, batching, ETA updates, optimization vs latency
Product search and recommendations Indexing pipeline, ranking, freshness
Payments and ledger Idempotency keys, double-entry bookkeeping, reconciliation
Notification system Fan-out, priority queues, deduplication
Order tracking and event pipeline Event sourcing, change data capture, replay
URL shortener, rate limiter, distributed cache Warm-up classics; be fast on these

For each design, prepare how it behaves at 10x traffic, when a dependency is down, and during a regional failover. At Coupang scale, answers are judged on how you degrade, not only on the happy path.

Prepare two production stories from your own work in this area: one performance problem you diagnosed using data, and one outage or defect you traced to its root cause. They double as behavioral material.

A8 Behavioral round and Bar Raiser

Build a bank of 6 stories, each with a number in the result, and map each story to two or three themes. Use the STAR structure (Situation, Task, Action, Result), keep each answer to about 2 minutes, and spend most of the time on Action and Result. Say "I" for your own decisions.

Theme Story prompt Your story (fill in)
Customer obsession A time you changed a design for the end user or client
Ownership Something outside your remit that you took end to end
Disagree and commit You disagreed with a decision, then executed it fully
Failure and learning A mistake you owned, and the fix
Delivering under pressure A hard deadline or production incident
Raising the bar You improved a team's engineering practice or mentored someone
Ambiguity and invention A vague problem you turned into a shipped solution

At principal level you are judged on scope and leverage, so at least two stories should show cross-team influence, a platform or process change, or a technical strategy you drove. Your AI-native engineering work (agent infrastructure, engineer-as-validator workflow) is strong material for the invention and raise-the-bar themes; bring before-and-after metrics.

Sample prompts to rehearse aloud

  • Tell me about a time you pushed back on a stakeholder and were proven right or wrong.

  • Describe the biggest technical risk you took, and what you did to limit it.

  • Tell me about a project that failed or shipped late. What would you change?

  • Describe a time you simplified something complex for customers.

  • How have you grown another engineer?

Research Coupang's customer-obsession and speed culture, and tie two of your stories to it.

A9 Step-by-step preparation

Follow these steps in order. Each has a concrete output so you can tell whether you are on track.

  1. Day 1: take a baseline. Solve two LeetCode Mediums in 45 minutes each, sketch one system design on paper, and write down every place you stalled. This list sets your weights, so adjust the plan to it.

  2. Day 2: set up your toolkit. Practice in plain Java in a basic editor. Prepare a one-page template for fast input and common imports, and a collections cheat sheet: ArrayDeque, PriorityQueue with comparators, TreeMap, HashMap iteration, Arrays.sort with lambdas, StringBuilder.

  3. Weeks 1-2: arrays, strings, hashing, binary search, stacks. Learn one pattern per day, then solve 5-8 problems on it. After each problem, note the pattern, the trigger phrase that reveals it, and the complexity. Re-solve anything that needed a hint after 3 days.

  4. Weeks 3-4: trees, graphs, heaps, intervals, backtracking. Write BFS, DFS, topological sort, union-find and Dijkstra from memory until each takes under 5 minutes. Finish with 2 timed mocks of two problems in 60 minutes.

  5. Week 5: dynamic programming and Java concurrency. Do DP in the mornings (1D, then 2D, knapsack, string DP) and concurrency in the evenings: a thread-safe LRU cache, a bounded blocking queue and a token-bucket limiter. Read a real thread dump and GC log once.

  6. Week 6: low-level design. Learn the seven patterns, then code one design every two days in 45 minutes: entities and interfaces first, then the core flow, then one extension. Keep each as a small Maven project with 2-3 unit tests.

  7. Weeks 6-7: databases and messaging. For PostgreSQL, practice reading EXPLAIN ANALYZE, designing composite indexes and explaining isolation anomalies. For Kafka and Redis, build a small producer-consumer app with a dead-letter queue and a Redis-backed cache with TTL.

  8. Week 7: high-level design. Do 8 designs from the table in A6, each on paper in 40 minutes with capacity math. Study Part B of this document alongside. Redo the weakest two a few days later and practice explaining one in 10 minutes.

  9. Throughout: behavioral stories. Write 2 STAR stories per week until you have 6, each with a metric. Rehearse aloud, record yourself once, and trim each to 2 minutes.

  10. Week 8: mocks and polish. Run 3 full loops (coding, LLD, HLD, behavioral) with a peer or a mock platform. Fix the top 3 recurring mistakes, such as skipping edge cases, forgetting complexity, or not stating trade-offs.

  11. Interview day. Sleep well, test your setup for remote rounds, and think aloud. If stuck, state the brute force and ask a clarifying question rather than going silent. In design rounds, drive the conversation: requirements, numbers, diagram, deep dive, failures.

A11 Final-week checklist and sources

  • Re-solve your 20 weakest problems without notes.

  • Rehearse 4 system designs aloud, with capacity math.

  • Code 2 low-level designs end to end in 45 minutes.

  • Rehearse all 6 STAR stories with metrics, timed at 2 minutes.

  • Prepare 5 questions for interviewers (team scale, on-call, technical roadmap).

  • Confirm round formats and language options with the recruiter.
